# v0.9.10 Stability Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Windows RWMCP self-converging and resistant to duplicate supervisors, restart storms, lifecycle races, and transient GitHub release-download failures.

**Architecture:** Extend the existing desired-state/recovery supervisor with persisted lifecycle epochs, convergence checks, and a bounded recovery circuit breaker. Preserve the v0.9.9 cross-process start lock. Add explicit update/restart interlocks and a SHA-verified GitHub API fallback for Linux release assets.

**Tech Stack:** Windows PowerShell 5.1, Node.js/TypeScript, GitHub Actions Windows/Linux runners, existing Control Center/runtime supervisor.

**Spec:** `docs/superpowers/specs/2026-09-17-v0.9.10-stability-hardening-design.md`

## Global Constraints
- Control Center 8684 remains loopback-only and independent of runtime/tunnel lifecycle.
- Manual Stop must remain authoritative.
- No destructive process cleanup unless managed ownership is provable.
- No SSH dependency in v0.9.10 acceptance.
- All release downloads remain SHA-256 verified.
