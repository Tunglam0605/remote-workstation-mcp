# v0.9.7 Autonomous Recovery Supervisor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Windows RWMCP autonomously return to the owner's desired running state without SSH or manual tunnel restarts.

**Architecture:** Persist owner desired state outside version slots, let the persistent Control Center host evaluate it, and recover through the stable launcher with bounded backoff. Planned boot/update/restart work uses a maintenance deadline so the watchdog never races valid lifecycle transactions.

**Tech Stack:** TypeScript/Node.js, Windows PowerShell 5.1, existing stable launcher, Control Center, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-17-v0.9.7-autonomous-recovery-design.md`

## Global Constraints

- Control Center 8684 remains independent of MCP/tunnel lifecycle.
- Manual Stop must persistently disable autonomous runtime recovery.
- No SSH/LAN dependency is allowed in the normal recovery path.
- Recovery actions use only the stable launcher and managed runtime state.
- Existing update/restart rollback and transaction behavior must remain intact.
