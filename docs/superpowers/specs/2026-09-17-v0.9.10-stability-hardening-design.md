# v0.9.10 Stability Hardening Design

## Goal
Make Windows Remote Workstation MCP converge autonomously to exactly one healthy runtime/tunnel/control stack and resist restart storms, stale supervisors, lifecycle races, and transient release-download failures without SSH or manual rescue.

## Architecture
The persistent Control Center remains the owner-local recovery authority. Runtime lifecycle operations share one external lock and one persisted lifecycle epoch. A convergence pass validates supervisor ownership, listener ownership, tunnel multiplicity, heartbeat freshness, and maintenance state. Recovery is bounded by a circuit breaker so repeated failures increase cooldown instead of creating restart storms. Update and rollback explicitly publish maintenance/interlock state so recovery never races planned lifecycle work. Linux updater gains a verified GitHub API asset fallback for transient browser-download 5xx responses.

## Invariants
- Exactly one managed Windows runtime supervisor may own MCP port 8683.
- Exactly one tunnel client may belong to the active managed runtime.
- Control Center 8684 remains independent and loopback-only.
- Manual Stop persists desiredRunning=false and suppresses autonomous restart.
- Update/restart/rollback hold an explicit lifecycle maintenance interlock.
- Recovery never spawns a new runtime while another lifecycle transaction owns the start lock.
- Recovery retries are bounded by exponential cooldown and persisted counters.
- Download fallback must use the exact release asset and verify SHA-256 before installation.
- No SSH/LAN dependency is allowed in acceptance after Windows reaches v0.9.10.

## State
Persist outside version slots under the managed runtime directory:
- `desired-state.json`: owner desired state and maintenance deadline.
- `lifecycle-state.json`: monotonic epoch, current transaction kind, owner PID, started/updated timestamps.
- `recovery-circuit.json`: consecutive failure count, cooldownUntil, lastReason, updatedAt.
- `recovery-supervisor-state.json`: heartbeat/liveness only.

## Convergence Rules
A convergence evaluation may take action only when desiredRunning=true and maintenance is inactive. It verifies active supervisor state first. If the recorded supervisor is stale, the state file is cleared. If multiple runtime hosts or tunnel clients are present for the managed install, only processes descending from the recorded active supervisor are retained; unrelated/ambiguous processes are logged but not killed automatically unless ownership is provable. If no valid supervisor remains, recovery requests StartOpenAI through the stable launcher.

## Circuit Breaker
Recovery actions use cooldowns 2, 4, 8, 15, 30, 60 seconds. After six consecutive failed recovery actions, enter a 5-minute open state. A healthy MCP+tunnel evaluation resets the breaker. Planned lifecycle maintenance does not increment failures.

## Update Interlock
Boot/Update/Rollback/Restart set lifecycle transaction state before mutating processes and clear it only after healthy completion or explicit failure recording. Autonomous recovery reads both desired-state maintenance and lifecycle-state transaction status and remains passive while a valid transaction owner is alive.

## Linux Download Fallback
`update-user.mjs` first uses the normal browser download URL. On HTTP 5xx only, it resolves the release asset via GitHub API, downloads `browser_download_url`/asset API with `Accept: application/octet-stream`, then verifies the SHA-256 from release `SHA256SUMS.txt`. 4xx, checksum mismatch, or mismatched asset names fail closed.

## Acceptance
Windows v0.9.10 must pass without SSH/manual rescue:
1. concurrent Start requests -> one supervisor/one MCP listener.
2. kill WebUI child -> 8684 recovers.
3. kill tunnel client -> tunnel reconnects.
4. kill runtime supervisor -> autonomous recovery returns MCP+tunnel.
5. kill recovery worker -> Control Center heartbeat watchdog replaces it.
6. create stale supervisor state -> convergence clears it and restores one runtime.
7. induce repeated failed recovery -> circuit breaker opens, preventing restart storm.
8. manual Stop -> runtime stays stopped for at least 2 recovery intervals.
9. Restart and Update -> maintenance/interlock prevents duplicate runtime creation.
10. 15-minute soak -> one runtime host, one MCP listener, one tunnel client, healthy heartbeat, no repeated EADDRINUSE/restart storm.
