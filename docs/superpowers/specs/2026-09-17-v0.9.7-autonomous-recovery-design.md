# v0.9.7 Autonomous Recovery Supervisor Design

## Goal
Make Windows RWMCP self-recover without LAN/SSH/manual intervention whenever Control Center remains alive and the owner has not explicitly stopped the runtime.

## Invariants
- Control Center on 127.0.0.1:8684 is the recovery authority and must stay independent of MCP/tunnel lifecycle.
- `desired-state.json` is the owner intent source of truth.
- `desiredRunning=true` means missing/unhealthy MCP or stale tunnel must trigger bounded autonomous recovery.
- Explicit owner Stop sets `desiredRunning=false` and suppresses recovery until a Start/Boot action changes intent.
- Planned maintenance suppresses recovery during update/restart/rollback windows.
- SSH is break-glass only and is not part of normal recovery or acceptance.

## Recovery policy
- Missing supervisor: start runtime immediately when desiredRunning=true.
- MCP unhealthy continuously for 15s: request runtime restart.
- OpenAI tunnel stale continuously for 90s: request runtime restart.
- Recovery backoff: 2, 4, 8, 15, 30, 60 seconds, capped at 60 seconds.
- Recovery actions must never overlap; one action process at a time.
- Healthy state resets recovery backoff and health timers.

## Components
- `scripts/windows-recovery-state.ps1`: atomic desired state + maintenance helpers.
- `scripts/autonomous-recovery-windows.ps1`: health evaluation and recovery actions.
- `scripts/control-center-host-windows.ps1`: watchdogs both WebUI child and autonomous recovery child.
- `scripts/runtime-control-windows.ps1`: keeps desired state synchronized with owner actions.
- `scripts/rwmcp-launcher-windows.ps1`: boot/update/rollback maintenance windows and intent preservation.

## Acceptance
Windows CI and a real Windows node must prove without SSH rescue:
1. Owner Stop remains stopped.
2. Missing runtime auto-starts.
3. Control Center WebUI child crash auto-recovers.
4. Tunnel client crash auto-recovers.
5. MCP/runtime process crash auto-recovers.
6. Restart/update maintenance does not fight the recovery worker.
7. After recovery, ChatGPT authenticated direct-node path returns healthy status.
